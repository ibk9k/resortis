# Arrival queue clarity and public checkout

## Report and evidence

The reported crowd is at the arrival promenade beside the café, palm and bin.
Ten-minute read-only replays of both the authored starter and the saved edited
resort found no stalled travel states. The edited-save replay recorded 36
different guests entering `waiting_room` near arrivals: later parties repeatedly
reuse the same spots while the four cabins are occupied. A completed stroll's
intentional seven-second rest is excluded from the travelling watchdog.

The minimal reproduction keeps one real starter cabin and advances the actual
runtime 50 seconds. Four additional customers wait for a vacancy. Before the
fix, five pairs have overlapping screen-space body regions and the queue has no
world explanation. `tests/arrival_wait_checks.gd` failed six assertions on that
version, then passed after the changes below.

## Change

- Waiting positions reserve the shared arrival/exit cell and allow enough
  screen space between standing customers, using actual reachable navigation
  cells. Existing saved positions remain intact.
- One world notice explains full cabins (or no suitable cabin), counts waiters,
  and shows the earliest party's remaining grace time. It disappears when the
  queue clears and follows simulation time, including pause and speed changes.
- The existing 32-second grace, booking rules, guest budgets and walking frames
  are unchanged. The regression also advances the queue through actual
  departure and checks that unaccommodated guests were never charged.

Native GPU inspection: `artifacts/arrival-wait-preview.png`, generated by
`tools/capture_arrival_wait.gd` using an isolated real scene. Player saves and
the open play session are untouched. Replays only cover the saved layout;
unsaved edits in an already running game are not captured by these tests.

## Repository preparation

Public repository: [ibk9k/resortis](https://github.com/ibk9k/resortis), branch `main`.

The public project includes source assets, baked runtime assets, scenes, tests,
and design/workflow documentation. `.gitignore` excludes all local artifacts,
player saves, engine/cache/export directories and credential files. Exact-byte
checkout attributes preserve reviewed source hashes. Commit attribution uses
the GitHub no-reply address.

The three independently captured cross-service rejection pairs are now retained
under `tests/fixtures/`, so a clean checkout no longer depends on old local QA
outputs. The launcher accepts an external Godot executable and creates its local
output directory; `check-assets.ps1` also creates that directory. Install Godot
4.7.2 Standard separately, import `project.godot`, and press F5.

The complete local gate passed: no failed/pending cases, including 2,877
integration assertions, 75 save checks, 596 population checks, both zero-hidden-
pixel GPU regressions, and all 776 reviewed hashes. Source graphics were not
rebaked or changed for this fix. The changed queue and the normal catalogue/
walking sheet were inspected in native renders.
